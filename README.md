# notjustlines

A static marketing website for an architecture and construction business in Accra. Built with Next.js, React, TypeScript, Tailwind CSS and Three.js.

## Run locally

```sh
npm ci
npm run dev
```

For the production export:

```sh
npm run build
npm run preview -- 3087
```

Open http://127.0.0.1:3087. `npm start` also previews the export, on port 3000 by default. The preview server binds to the local machine; it is not a public production server. The build generates responsive WebP images automatically before exporting to `out/`.

`npm run typecheck` runs TypeScript separately. The existing `next lint` command needs an ESLint configuration before it can run unattended. Google fonts are fetched by Next at build time; a fresh build needs access to Google Fonts or a populated font cache.

## Which files are authoritative?

- `src/app/`: the main multi-page website. Its home page is `src/app/page.tsx`.
- `src/lib/site.ts`: brand, domain and contact configuration. The phone and email were retained from the existing project and have not been independently verified.
- `src/data/projects.ts`: illustrative scenarios, not verified client case studies. Existing URLs are retained for compatibility, including the older atelier slug.
- `src/components/ConversationalBrief.tsx`: the four-step enquiry composer.
- `public/assets/`: source images and generated responsive variants. Run `npm run images` after replacing an image, or run the build.
- Root `index.html` and `coming-soon.html`: standalone holding pages. They are not the Next.js homepage. Their notjustlines branding and email address are maintained separately.
- `public/coming-soon.html`: the holding page included in the export.
- `public/legacy-index.html`: redirects old visitors to the current homepage.

For normal deployment, upload the contents of `out/`, not the repository root. Configure the static host to resolve extensionless routes to their `.html` files and serve `404.html` for missing routes. Do not copy the root holding page over the exported homepage.

## Enquiry behaviour

The brief gathers a request, property details, optional readiness/budget information and contact details. It has no API, database, analytics collector or automatic email delivery.

1. Answers live in component memory and disappear on reload or navigation away.
2. The review screen explicitly says the brief has not been sent.
3. WhatsApp opens a prefilled message. Email opens a prefilled draft in the visitor's email application. The visitor must send it there.
4. Copy lets the visitor use another application. If clipboard access fails, the text remains selectable and the destination contact details remain visible.
5. There is no claimed delivery confirmation or promised response time.

Budget is an optional client-provided amount in a selected currency. There is no construction rate calculation, currency conversion or quote generated by the site. Unknown area, budget and start date remain unknown rather than being assigned assumed values.

## Content and launch checks

- Brand confirmed by the owner: **notjustlines**.
- Confirm the configured domain, inbox and WhatsApp/phone number before publishing. Actual message delivery has not been tested.
- The old Instagram link is hidden. Add an approved account to `SITE.instagramUrl` before restoring it.
- Replace illustrative project content only when descriptions, completion status, locations, photographs and permission to publish are verified. Do not turn the existing example images into claimed client work.
- Confirm image usage rights, business registration details, team identities and service capacity before adding factual claims about them.
- Service descriptions now frame scope, payments, supervision and reporting as matters to agree in a proposal. No fixed pricing, permit outcome, warranty duration or response-time promise is published.
- If durable lead capture is needed, choose and configure the receiving service first; add real submission, error handling and delivery confirmation before changing the current wording.
